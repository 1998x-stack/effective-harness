LAUNCH
Execute Agent Session Protocol
Every session follows a strict 7-step startup sequence before touching any code — verification before progression.
  1. 1pwd — confirm working directory
  2. 2Read .claude-progress.txt — understand session history
  3. 3Read feature_list.json — find highest-priority pending feature
  4. 4git log --oneline -20 — review recent code changes
  5. 5./init.sh — start dev environment and verify smoke test
  6. 6git status --porcelain — detect dirty tree from crashed session
  7. 7Select feature + implement → verify → commit → clean exit
SPEC
Feature List Format JSON
Every feature starts passes: false — guilty until proven working. Execute Agent may ONLY toggle passes; all other fields are immutable.
feature_list.json
{ "project": "Todo CLI", "features": [ { "id": "F001", "category": "setup", "priority": 1, "description": "Project scaffolding...", "steps": [ "Run go build ./... and confirm exit 0", "Run ./app --help and verify usage output" ], "passes": false } ] }

PRINCIPLES
Six Design Principles
PrincipleImplementation
Memory externalizationState lives in filesystem (JSON, text, git), not agent context
Immutable specificationFeature list write-once; only passes field can change
Incremental contractOne feature per session, merge-ready state every exit
Verification firstSmoke test every session before implementing new features
Human tools = agent toolsGit, JSON, shell scripts — no proprietary infrastructure
Simplicity firstTwo prompt files, one script, zero configuration
