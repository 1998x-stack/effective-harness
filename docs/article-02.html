双Agent模式：初始化器与编码器

两个角色、同一套工具、不同的prompt——极简但精准的职责分界

一、为什么需要两个Agent？

"We addressed these problems using a two-part solution: 1. Initializer agent — the very first agent session uses a specialized prompt. 2. Coding agent — every subsequent session makes incremental progress."

这不是两个不同的模型或Agent系统，而是同一个Agent在不同阶段被赋予不同的system prompt。系统提示词、工具集、基础设施完全一样，唯一不同的是初始用户prompt的差异。

二、初始化Agent：打地基的人

初始化Agent只在首次会话中执行。它的使命不是写业务代码，而是搭建一个可以让后续所有编码Agent高效工作的环境地基。

产出物说明作用
init.sh启动开发服务器的脚本每个后续Agent无需自己摸索如何启动App
.claude-progress.txt进度日志文件Agent间的"交接文档"
初始Git Commit记录初始文件结构提供版本回溯基准线
"The key insight was finding a way for agents to quickly understand the state of work when starting with a fresh context window."

让Agent能从零上下文窗口在最短时间内恢复对整个项目状态的认知——不是通过复杂的记忆系统，而是通过一个朴素的文本文件和git历史。

三、编码Agent：迭代推进的人

编码Agent在所有后续会话中运行。它的设计围绕一个核心原则：增量推进，干净离开。

"The coding agent was asked to work on only one feature at a time. This incremental approach turned out to be critical to addressing the agent's tendency to do too much at once."

一次只做一个特性。这直接对抗了"试图一次做完所有事"的失败模式。

会话结束协议：干净状态

"We found that the best way to elicit this behavior was to ask the model to commit its progress to git with descriptive commit messages and to write summaries of its progress in a progress file."
  • Commit意味着Agent必须确认代码是可编译、可运行的
  • 进度摘要意味着Agent必须清晰地表达"我做了什么、下一步该做什么"

四、角色分离的设计哲学

让一个Agent既理解全局需求、又逐特性增量实现、还要维护环境——这个任务本身就要求同一时间处理太多不同的认知模式。分开之后，每个Agent的prompt可以更聚焦、更精确。

"It seems reasonable that specialized agents like a testing agent or a code cleanup agent could do an even better job — but it's still unclear whether a single, general-purpose coding agent performs best, or if better performance can be achieved through a multi-agent architecture."

能用两个解决的问题，不要引入第三个——直到数据证明你需要更多的复杂度。
